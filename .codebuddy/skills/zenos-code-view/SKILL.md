# zenos-code-view：代码注释

给已有代码补充清晰、有价值的注释，让阅读者快速理解「这段程序在做什么、为什么这么做」。

核心原则：**只加注释，不改逻辑**。原有代码、变量名、控制流、格式一律保持原样，只在其周围插入注释行或文档注释块。

## 何时使用

- 用户要求「给 X 加注释」「把这段代码注释一下」「注释掉的不是删除，是说明」。
- 用户想理解一段陌生代码，需要逐行/逐块解读。
- 为函数、类、接口补全文档注释（参数、返回值、异常、用途）。
- 新人接手、代码评审前、交付前提升可读性。

不适用：用户要的是重构、修 bug、改实现、加功能、删除代码、或把代码「注释掉（禁用）」——那些不是本 skill 的职责，按普通编码任务处理。

## 工作流程

1. **确定目标**：明确要注释的是整个文件、某个函数/类、还是一段选中的代码。范围不明时先用一句话向用户确认，不要擅自给整个仓库加注释。
2. **通读代码**：先完整读一遍目标代码及其上下文（调用方、被引用的类型/常量），确保注释描述准确，不要凭名字猜测。
3. **识别重点**：找出值得注释的位置（见下「注释原则」），跳过一目了然的语句。
4. **写回注释**：用 Edit 工具在原位置插入注释。保持原有缩进、空行、换行风格。
5. **复核**：确认没有改动任何非注释字符；确认注释语法符合对应语言，不会破坏代码。

## 注释原则（重要）

- **解释「为什么」优先于「是什么」**：好的注释说明意图、约束、业务背景、边界条件、取舍原因；不要写 `i++ // i 加 1` 这种复述代码的废话。
- **注释「不明显」的部分**：复杂算法、位运算、正则、状态机、隐式约定、魔法数字/字符串、易踩的坑、与直觉相悖的写法、跨模块的副作用。
- **公开接口给文档注释**：函数/方法/类说明用途、参数含义与取值、返回值、可能抛出的异常/错误码、线程安全或性能约束。私有内部函数按复杂度酌情。
- **准确、克制、可维护**：注释必须与代码一致；不写冗余、不写情绪化内容、不写待办式废话；避免大段复制粘贴。语法正确，别把可执行代码包进注释导致编译不过。
- **用中文**：与用户沟通及注释正文使用简体中文（标识符、类型名、专业术语、既有英文注释保持原样）。
- **不臆造逻辑**：看不懂或信息不足处，写「此处逻辑需结合调用方确认」之类，或向用户提问，绝不编造功能描述。

## 各语言注释语法

| 语言 / 场景 | 行注释 | 块 / 文档注释 |
|---|---|---|
| C / C++ / Java / Go / JS / TS / Rust / C# | `//` | `/* */`；Java `/** Javadoc */`、JS/TS `/** JSDoc */`、Rust `///` 文档注释 |
| Python | `#` | 函数/类下方三引号 `"""docstring"""` |
| Shell / Ruby / YAML / Makefile / TOML | `#` | — |
| SQL | `--` | `/* */` |
| HTML / XML | — | `<!-- -->` |
| CSS | — | `/* */` |
| Lua | `--` | `--[[ ]]` |
| Go 导出标识符 | `//` | 紧贴声明上方 `// Name ...` 形式的 doc comment |

始终沿用该文件已有的注释风格（如已有 JSDoc 就用 JSDoc，已有 `#` 就用 `#`），不要混用。

## 注释密度与位置

- 文件头：仅在能说清该文件整体职责、且不会很快过时的时候加，避免「这是 XXX 文件」式空话。
- 函数上方：一段文档注释概括用途 + 参数/返回/异常；函数内部只在关键分支、难懂步骤处加行注释。
- 复杂块前：用 1~2 行说明该块的目标与思路，再在关键行补充。
- 行尾注释：只用于解释单个常量的含义，且保持简短。
- 不要每一行都加注释；注释是路标，不是逐字翻译。

## 输出规范

- 默认**直接把注释写回源文件**（用 Edit），并在回复里简要说明补了哪些注释、大致位置。
- 若用户只想「看解读」而不想改文件，则输出带注释的代码块或逐段说明，不写文件。
- 改动较多时，列出「新增注释的位置 + 要点」清单，方便用户核对。
- 完成后确认：原有逻辑零改动、注释语法正确、无编造内容。

## 示例

原始代码：

```python
def calc(items, rate):
    total = 0
    for it in items:
        if it["status"] == 2 and it["amount"] > 0:
            total += it["amount"] * rate * 0.95
    return round(total, 2)
```

加注释后：

```python
def calc(items, rate):
    """按费率计算有效订单的结算总额。

    Args:
        items: 订单字典列表，需包含 status 与 amount 字段。
        rate: 结算费率（如 0.06 表示 6%）。

    Returns:
        保留两位小数的结算总额。
    """
    total = 0
    for it in items:
        # status==2 表示「已完成」；amount>0 过滤退款/异常单，避免把负数计入结算。
        if it["status"] == 2 and it["amount"] > 0:
            # 0.95 为平台优惠系数（固定 5% 让利），与 rate 相乘得到实际结算比例。
            total += it["amount"] * rate * 0.95
    return round(total, 2)
```

注意：只新增了文档注释与两处行注释，计算逻辑一字未改。
